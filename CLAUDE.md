# CLAUDE.md — Šank

Internal order + shift + bar-stock + owner-dashboard app for one shisha lounge in Bosnia and Herzegovina. The master plan (data model, flows, rules, roadmap, open decisions) lives in **PLAN.md** — read it before any task. Research appendices are in `docs/research/`, the review history in `docs/reviews.md`.

## Owner context

- Vedran is a **junior web developer trained only on Vue 3 / Nuxt** — explain non-Vue concepts (transactions, triggers, WAL, service workers, ETag, scrypt, moving average) in a two-line comment or README paragraph where they first appear; never assume backend/devops experience beyond what `~/Projects/snajper` already ships.
- Model split: **Fable plans and reviews, Opus 5 implements** via subagents, one PR per roadmap bullet or coherent slice. After each phase: `nuxt build` + typecheck + vitest + a visual check on a phone-sized viewport (real phone for offline work), then commit.
- The café owner is Vedran's friend. One venue now; `venue_id` on every table so a second café is an insert, not a rewrite.

## Stack & conventions

- Nuxt 4 (Vue 3 + TypeScript, `<script setup>`), Tailwind CSS v4, Pinia + VueUse, Drizzle ORM + better-sqlite3 (WAL), Nitro server routes, Zod schemas in `shared/`, vitest. Same folder shape as snajper: `app/`, `server/`, `shared/`, `deploy/`, `tests/`.
- Two layouts: `/k` — waiter app (dark theme, mobile-first, installable PWA, offline outbox with client UUIDs); `/a` — owner dashboard (phone + laptop).
- UI language Bosnian (ijekavian). Money is integer feninga in `*_fen` columns, formatted `1.250,50 KM`; dates `08.09.2026.`; 24 h clock; the business day starts 06:00 `Europe/Sarajevo` — no business code calls `getHours()` without a zone (`shared/dates.ts`).
- Ledger tables are append-only, enforced by SQLite triggers in `server/database/triggers.sql`, re-applied at boot after `migrate()`. The invariant tests are the guardrail: never weaken one to fit a feature; a test change needs a sentence in the PR naming the invariant that moved. `tests/unit/invariants.test.ts` holds the four cross-package identities (the summary reconciling three ways, `venueExpected = drawer + Σ waiters`, *Puls* against the ledger, *Kategorije* against the written summaries).
- **Three roles: `admin | waiter | bartender`.** `'owner'` is not an accepted value anywhere after the Korak 2 migration — the owner *dashboard* is `/a` and the role guarding it is `admin`. Authorization is deny-by-default through one table, `shared/routeRoles.ts`: `server/middleware/tenant.ts` normalises `method + path` and **403s when the key is absent**, so a route nobody declared is dead rather than open. `tests/unit/route-roles.test.ts` asserts `ROUTE_ROLES` and `server/api/**` are the same set, both directions.
- **Sessions, not `user_id` in a body.** A phone enrols once with a six-character code and gets a device cookie; a person then PIN-logs in against that device. Every handler reads `event.context.actor` / `event.context.venueId`, which `tenant.ts` resolves from the cookies; no body ever names the actor and no handler reads a venue from a body or picks one itself. PINs are scrypt hashes with a pepper (`PIN_PEPPER`), every attempt at all three doors leaves an `auth_attempts` row, and lockout steps at 5 / 10 / 15 failures.
- The server never trusts a price or amount from a phone; prices are snapshotted at lock; stock is deducted inside the lock transaction; every phone-born row is idempotent (`UNIQUE(venue_id, client_id)`) and a replay returns 200 with the stored result, never 409.
- **One poll.** Every mutating transaction calls `bump(tx, …)`, which appends to `changes`; `GET /api/changes?since=<seq>` is the single timer on every screen (15 s), ETagged with the role *and* user in the tag. `tests/unit/changes-coverage.test.ts` walks `server/api/**` and fails on a mutation that does not bump or is not an exempted non-event.
- Migrations only (`drizzle-kit generate` + `migrate`); never `drizzle-kit push` against real data. Korak 2 is one migration, `0001_korak2.sql`.
- Secrets live in `/opt/sank/.env` on the VPS only; nothing secret ships to the client. The one the app cannot run without is `PIN_PEPPER` — there is no session secret, because sessions are random tokens stored as sha256 and there is nothing to sign. `SANK_DEV_ENROL=1` is a dev-only door and is never set on the server. `.env.example` is the local list; `deploy/deploy.env.example` is the server's.
- Scheduled work is three Nitro tasks in one process (`server/tasks/{nightly,alerts,backup}.ts`), scheduled in UTC because `deploy/sank.service` sets `TZ=UTC`; anything that needs the café's wall clock goes through `shared/dates.ts`. They are no-ops under vitest.
- **Bosnian only, no i18n layer.** Every UI string, Telegram message and log title is written in Bosnian (ijekavian) directly in the code; no English on any screen, no translation library. English stays in identifiers, comments and docs. `PLAN.md` §12 is the glossary — reuse its labels verbatim.
- One activity record: `log_entries` (written by `log()` inside the same transaction as the event, so an entry exists only if the event committed) feeds the owner-only *Dnevnik* page and the Telegram mirror; there is no separate `audit_log`. `shared/logTemplates.ts` is frozen for Korak 2: `kind` is typed, every kind has a Bosnian title template, and the ✔ column names which of `ALERT_RULE_KEYS` it mirrors. Locks and payments are deliberately **not** entries — they are the ledger. Chat (`chat_*`), uploads and the roster tables follow the same venue_id / client_id conventions; chat access is one `canSee(role, kind)` function enforced on every read, write and image URL.
- The waiter's end of shift is one flow: the cash settlement (*Završi smjenu*). Do not add a second end-of-shift; extend that one.

## Sensitivity notes

- **Not a fiscal device.** No receipts, no printing, no PDV lines, no receipt numbering; the word *račun* appears only in "Na račun kuće". Keep the disclaimer in README and the watermark on *Pokaži narudžbu*.
- **Konobari is private.** Owners never see the *Konobari* channel in the app (server-enforced); *Dnevnik* and drill-downs are owner-only; no per-person money ever appears in *Svi* or *Konobari*. The honesty note about the database file is published in *Pravila* — keep it truthful.
- **Accountability, not surveillance.** Staff see their own numbers first; flags say "označeno za razgovor", never accuse; no leaderboards; thresholds are published in *Pravila* inside the app. Read PLAN.md §8 before touching any per-person metric.
